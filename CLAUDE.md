# EngineX OS — notes for AI agents

Custom system rebuilt on the official Engine OS 5.3.0+ base for 16 Denon DJ / Numark / Rane standalone units: 8 first-generation models as AZ01 `*-Update.img` (3 image groups) and 8 second-generation models unified on `*-Update.img` `/data`-bundle images (6 armhf on SC LIVE 4's Engine, PRIME 4 G2 / SYSTEM ONE on the 64-bit AZ04 Engine; `5.3.0.4`/`5.3.0.5` Releases also keep the 8 `*-Data-Bundle.tar.gz` archives alongside `*-Update.img` for legacy Gen-2 OTA compatibility before retiring them in `5.3.0.6+`, #215). Engine 5.0.4 is no longer developed: new work targets 5.3.0+ only. Read [`CONTRIBUTING.md`](./CONTRIBUTING.md) first.

- **Maintainer's developer handbook (private)**: if your GitHub login can read the private repo `Cd1s/EngineX-OS-internal`, clone it next to this repo (or `git pull` the existing clone) and, before developing or hunting a bug, read the first page of `docs/ENGINEX-DEVELOPER-HANDBOOK.md` and the section its keyword index gives for your area. This is a duty (a check on 2026-11-22 found that no agent session had opened it): your report lists the sections you used. If you cannot read it, skip this line. Never copy its content into this public repo, Release Notes, Issues or PRs.
- **Releases**: read [`.claude/rules/release-workflow.md`](./.claude/rules/release-workflow.md) before any release step (it loads by itself only when you touch the release files) and follow it step by step: version file, all three READMEs, `https://enginexdj.com` docs website & OpenGL screenshots, build (16 `*-Update.img` [8 Gen-1 + 8 Gen-2] + 8 legacy-OTA `*-Data-Bundle.tar.gz` + 4 `EngineX-Installer` = 28 release artifacts in `5.3.0.4`/`5.3.0.5`), image checks, 3 release gates, signing `SHA256SUMS.txt` (`sign-release.sh`, #239; the private key stays on the build host), tag, Release Notes SHA-256 table, Issue notifications, change record, and post-release disk cleanup on the build host.
- **Version**: stays at the current one (5.3.0.5) unless the maintainer explicitly asks for a new version. Fixes are re-released over the same Release with `--clobber`.
- **Build and test in three tiers**, never on the maintainer's laptop. **Fast tier** = pure Go and Python tests on the x86 host through `tools/dev/test.sh` (targeted at the files you changed; `--full` for everything; the hosts come from `ENGINEX_FAST_HOST` and `ENGINEX_BUILD_HOSTS`, set in the environment or `~/.config/enginex/dev.env`). **ARM tier** = armhf-native tests, sandboxes, gates and release builds on the build host (aarch64 with 32-bit EL0, so the deck's armhf code runs natively): `REMOTE_BUILD_HOST=<build host> remote-build ...` under the heavy lock (the script defaults to another host); the unit tests that need it are listed with a reason in `tools/dev/arm-tests.txt`, and `test.sh` runs them there at the same time as the fast tier. A **release candidate** runs everything uncached on the ARM build host as `.claude/rules/release-workflow.md` step 2 says. Host aliases and the `REMOTE_BUILD_HOST` value are in the private developer handbook. Firmware, qrc and `fsck.hfsplus` live in `<firmware-lab>/` there. Use a fresh `--clean` directory for release builds, and always clean up `/root/build/*` (except the read-only firmware lab), `/var/tmp/*`, and `/tmp/*` after building/testing so the build host disk never fills up.
- **Experimental inspection & component analysis**: use **`craft-anything`** (`craft-anything` skill / `craft-anything-cli`) with **Gemini 3.8 Flash** on the build host to inspect software components, QML resources, and ABI compatibility interfaces (since 2026-11-13; DeepSeek has no quota left).
- **Never trigger Factory Reset or `az01-update --erase-data` on a real deck**; test them with `unshare -m` + chroot on the unpacked rootfs on the build host.
- **Three READMEs** (`README.md`, `README.zh-CN.md`, `README.zh-TW.md`) are written once at release (see the Docs website bullet), change together and keep the current layout: aligned grids, few emojis, direct download links (4 `EngineX-Installer` + 8 Gen-1 `*-Update.img` + 8 Gen-2 `*-Update.img` = 20 primary links per README, noting `*-Data-Bundle.tar.gz` is also in Releases for `5.3.0.2`/`5.3.0.3` OTA).
- **Stock way, lowest cost**: let stock logic do the work and add no cost while playing or browsing. Choose in this order, and say why the earlier ones do not work before taking a later one: (1) a capability Engine already provides (a built-in setting, a board flag, a config value); do not add an EngineX switch that duplicates a stock one; (2) correct the data once, at insert, at boot or in the background, and let stock logic run; (3) our own Go code; (4) a hook in Engine; (5) QML only for what the screen shows, never to cover a data or logic problem. Every fix states its cost while playing, while browsing and at insert.
- **No regressions**: a fix must never bring back an old bug or cause a new one. Before changing a mechanism, look up the issues it already fixed (`git log -S`, the issue numbers in tests and `docs/ISSUE-FIXES-*.md`) and keep their tests green. Every fix ships with a regression test that fails on the old code. A fix to a shared mechanism (MASTER/sync election, hook sites, header layout, patch dicts) also tests the neighbouring behaviours. Never delete or weaken an existing test to make a change pass. Every new real-deck bug adds a line to [`docs/REGRESSION-CHECKLIST.md`](./docs/REGRESSION-CHECKLIST.md).
- **Evidence first**: read the deck journal, library rows, cache files, settings, and screenshots for the reported symptom before changing code. A fix counts only when the deck shows the code path firing and the symptom is gone.
- **Deck push first**: test each fix with deck-push first. When an image is really needed, build only the SC5000 JP07 `*-Update.img` with `ONLY_GROUP=SC5000`; build the full package and run the full gates only for a release candidate.
- **Lane test rule**: a lane runs its fail-before/pass-after and `tools/dev/test.sh` (targeted) only. Reviewers read the diff and run `tools/dev/test.sh` (targeted). The full suites run only in the merge train: `tools/dev/integrate.sh` calls `test.sh --full` once per merge batch.
- **SC5000-only build**: `ONLY_GROUP=SC5000 sh tools/az01-packer/build-release.sh ...` emits only the SC5000 group `*-Update.img` files and skips other groups, Gen-2 bundles, installers, and signing.
- **Tools**: use Serena MCP symbol tools to find functions/types and references when reading or editing Go, C, and Python instead of reading whole files. Search basic-memory MCP project `enginex-internal` for earlier findings before starting, then write the one key finding there when done, never secrets. Use `systematic-debugging` for root-cause investigation and `verification-before-completion` to show command output before claiming completion when available.
- **No secrets or private names** in commits, Release Notes or logs: keys, tokens, Deezer ARL, passwords, the maintainer's private domains and host names.
- **Docs website**: `docs/index.html` + `docs/site/{content.js,app.js,style.css}` is the trilingual (zh-CN / zh-TW / en) user guide, served by GitHub Pages or opened locally. During development nobody edits the website (`docs/index.html`, `docs/site/`), the three READMEs, screenshots or release notes (maintainer, 2026-11-21: 「不用更新官网和文档这些 真正发布的时候才弄的」): they are written once at release (release-workflow step 1) from the merged changes. A lane's report says in one line what the user will see. Tests and `docs/REGRESSION-CHECKLIST.md` rows stay mandatory. Runtime path is `/data/enginex/` (legacy layout readers are isolated in the migration files).
