# EngineX OS — notes for AI agents

Custom system rebuilt on the official Engine OS 5.3.0+ base for 16 Denon DJ / Numark / Rane standalone units: 8 first-generation models as AZ01 `*-Update.img` (3 image groups) and 8 second-generation models unified on `*-Update.img` `/data`-bundle images (6 armhf on SC LIVE 4's Engine, PRIME 4 G2 / SYSTEM ONE on the 64-bit AZ04 Engine; `5.3.0.4`/`5.3.0.5` Releases also keep the 8 `*-Data-Bundle.tar.gz` archives alongside `*-Update.img` for legacy Gen-2 OTA compatibility before retiring them in `5.3.0.6+`, #215). Engine 5.0.4 is no longer developed: new work targets 5.3.0+ only. Read [`CONTRIBUTING.md`](./CONTRIBUTING.md) first.

- **Maintainer's developer handbook (private)**: if your GitHub login can read the private repo `Cd1s/EngineX-OS-internal`, clone it next to this repo and read the matching chapter of `docs/ENGINEX-DEVELOPER-HANDBOOK.md` before developing or hunting a bug. If you cannot read it, skip this line. Never copy its content into this public repo, Release Notes, Issues or PRs.
- **Releases**: follow [`.claude/rules/release-workflow.md`](./.claude/rules/release-workflow.md) step by step: version file, all three READMEs, `https://enginexdj.com` docs website & OpenGL screenshots, build (16 `*-Update.img` [8 Gen-1 + 8 Gen-2] + 8 legacy-OTA `*-Data-Bundle.tar.gz` + 4 `EngineX-Installer` = 28 release artifacts in `5.3.0.4`/`5.3.0.5`), image checks, 3 release gates, tag, Release Notes SHA-256 table, Issue notifications, change record, and post-release disk cleanup on the build host.
- **Version**: stays at the current one (5.3.0.4) unless the maintainer explicitly asks for a new version. Fixes are re-released over the same Release with `--clobber`.
- **Build and test only on the build host** (aarch64 with 32-bit EL0, so the deck's armhf code runs natively), never on the maintainer's laptop. Since 2026-11-05 this project no longer uses IN: run `REMOTE_BUILD_HOST=<build host> remote-build ...` (the script still defaults to IN). Firmware, qrc and `fsck.hfsplus` live in `/root/build/sc5000-lab/` there. Use a fresh `--clean` directory for release builds, and always clean up `/root/build/*` (except `sc5000-lab`), `/var/tmp/*`, and `/tmp/*` after building/testing so the build host disk never fills up.
- **Experimental inspection & component analysis**: use **`craft-anything`** (`craft-anything` skill / `craft-anything-cli`) together with the **`deepseek-v4.1-flash`** (`deepseek4.1 flash`) model on the build host to inspect software components, QML resources, and ABI compatibility interfaces.
- **Never trigger Factory Reset or `az01-update --erase-data` on a real deck**; test them with `unshare -m` + chroot on the unpacked rootfs on the build host.
- **Three READMEs** (`README.md`, `README.zh-CN.md`, `README.zh-TW.md`) change together and keep the current layout: aligned grids, few emojis, direct download links (4 `EngineX-Installer` + 8 Gen-1 `*-Update.img` + 8 Gen-2 `*-Update.img` = 20 primary links per README, noting `*-Data-Bundle.tar.gz` is also in Releases for `5.3.0.2`/`5.3.0.3` OTA).
- **Stock first**: enable a capability Engine already provides (a built-in setting, a board flag, a config value) before building our own; do not add an EngineX switch that duplicates a stock one.
- **No regressions**: a fix must never bring back an old bug or cause a new one. Before changing a mechanism, look up the issues it already fixed (`git log -S`, the issue numbers in tests and `docs/ISSUE-FIXES-*.md`) and keep their tests green. Every fix ships with a regression test that fails on the old code. A fix to a shared mechanism (MASTER/sync election, hook sites, header layout, patch dicts) also tests the neighbouring behaviours. Never delete or weaken an existing test to make a change pass. Every new real-deck bug adds a line to [`docs/REGRESSION-CHECKLIST.md`](./docs/REGRESSION-CHECKLIST.md).
- **No secrets or private names** in commits, Release Notes or logs: keys, tokens, Deezer ARL, passwords, the maintainer's private domains and host names.
- **Docs website**: `docs/index.html` + `docs/site/{content.js,app.js,style.css}` is the trilingual (zh-CN / zh-TW / en) user guide, served by GitHub Pages or opened locally. Every time a feature, setting, menu path, model or download changes, update `docs/site/content.js` (all three languages) and the matching screenshot in the same commit; mark not-yet-released features with `tone: "new"` notes and remove them on release. Runtime path is `/data/enginex/` (the old `/data/sc5000-custom` is a compatibility symlink).
