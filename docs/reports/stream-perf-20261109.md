## 改动

- 网关元数据缓存统一覆盖普通视图、OmniSource、喜欢的歌曲、专辑曲目和公开 Deezer 榜单。Playlists 与 Tracks 分离，provider、登录 session、操作与原始 ID 组成 SHA-256 key；不同平台及 guest 不混用。Engine offset/limit 和 `/tracks`、`/items` 别名共用同一次上游拉取。重新登录生成新 session 后弃用旧私有命名空间。
- TTL 2 分钟；成功元数据过期后最多保留 24 小时，立即返回旧值，后台一个 90 秒 refresh；同 key 并发冷请求合并。刷新失败保留旧数据，5 秒退避；无成功数据时也暂存错误 5 秒，错误不落盘。HTTP 401/403 则清除内存/磁盘旧私有数据，恢复登录错误提示；成功快照超过 8 MiB 时不缓存新快照并淘汰旧快照，避免显示长期过时数据。
- 内存最大 32 MiB / 128 项，单项最多 8 MiB；最多 32 个进行中的不同 key。磁盘最多 64 MiB / 128 文件，临时文件原子替换、文件 0600、目录 0700。生产路径 `/data/enginex/cache/browse-v1`；测试使用临时 StateDir。写盘使用独立 diskMu，不阻塞已在内存中的命中；启动和写盘清理未完成的临时片段。写盘失败不阻止元数据返回。缓存不触碰音频下载、/data 下设置/数据库或 inMusicTempFiles。
- 磁盘只持久化播放列表/曲目元数据白名单结构，**不保存任何封面/缩略图/preview URL**，避免 signed URL 携带凭据；不序列化 Provider、Cookie、Token 或下载地址，也不打印 cache key 或凭据。磁盘恢复时直接显示旧元数据并立即后台刷新，补回只在内存保留的图片 URL；刷新前封面可能暂缺，这是明确取舍。
- 每个读取者拿到独立解码副本，BPM、评分、排序和 OmniSource 标题前缀不会污染缓存。
- Search 与 SearchPlaylists 同时开始，保留后续搜索分页返回空及各 provider 现有 fallback。未改 provider 分页算法，保留原平台顺序、局部成功与 Deemix 音频共享规则。

## 拿不准

- 不强制清缓存、切 scope 或修 DNS；严格保留打碟现场。当前两种 scope 的真实测量不能代表五个平台各自健康联网时的延迟，其余平台结论来自代码分析。
- 封面只通过已有行查询；未为计时而加载曲目。404 的样本是未注册图片映射，不能据此判断 CDN 热缓存命中速度。现有封面内存缓存保持原样。
- 私有磁盘缓存按 session 隔离，账号会话重建后不会直接复用旧账号结果；公开榜单可跨重启复用。优先隔离正确性，不引入读取/哈希凭据文件的新逻辑。
- 保留完整上游分页及现有排序语义；没有改成只抓首屏或并发抓分页。首屏冷启动仍有优化空间，需要健康网络下的下一轮测量。
- HTTP 401/403 清理针对 providers.StatusError；网易云/Deezer 的普通文字登录错误没有被猜测分类，仍可能按一般失败保留旧数据至 24 小时。冷磁盘读取仍在元数据锁内，冷调用者也要等待自身写盘；本轮优先解决反复上游等待和热命中阻塞。
- 元数据缓存不会修复 DNS，也不会清理 Engine 的 inMusicTempFiles。下载磁盘增长是另一项工作，本分支不扩大范围。

回滚：PM 部署前仅需不选此分支；部署后可回退二进制。新增 cache/browse-v1 为可丢弃元数据，不要求修改设置/数据库。没有生产服务变更。
